## v4.0.4 · 修复「双击程序没反应」· 修复「关于」页更新日志
*2026-10-06*

这一版修的是两个一用就会碰到的问题：双击 exe 有时完全没反应，以及「关于」页面里的更新日志一直显示成一行错误提示。

### 🐞 修复：双击程序没有任何反应
- **问题现象** — 双击 TK去水印高清程序.exe 后什么都没发生：没有窗口、没有托盘图标、连错误提示都没有；app.log 也一直是上次运行的时间。而单独用命令行跑 desktop.py 却完全正常。
- **根本原因** — 启动器在启动 Python 之前会先往子进程环境里塞两个变量，用的是 .NET 的 EnvironmentVariables 字典 —— 它是大小写不敏感的。这台机器的环境里同时存在 NO_PROXY 和 no_proxy 两个变量，于是赋值时直接抛 ArgumentException：「已添加项。字典中的关键字:“NO_PROXY”所添加的关键字:“no_proxy”」。
- **为什么此前一直没被发现** — 抛出异常的代码在窗体 Load 事件里，完全没有 try/catch。异常发生时窗体还没来得及显示、托盘也还没建立，进程就静默结束了，所以表现成「双击没反应」。
- **修复** — ① 启动器不再写那两个环境变量 —— 它们只服务于 v3 的 Python 托盘，而托盘早就由启动器自己负责，全项目已无任何代码读取它们，现在改为完整继承父进程环境。② 整个启动流程加上异常捕获，任何失败都会写进 launcher.log 并弹出提示，不会再出现「什么都没发生」。
- **附带清理** — 删掉了两处「死代码」重复定义（models_cards_html / presets_html / update_notice_html 的旧实现被后面的同名新实现覆盖）。其中旧的 presets_html 还引用了一个不存在的变量，一旦有人删掉新实现就会立刻报错。

### 🐞 修复：「关于」页面的更新日志显示失败
- **问题现象** — 「设置 → 关于」里的更新日志只有一行：「（更新日志读取失败：module 'core.changelog' has no attribute 'get_changelog'）」。
- **根本原因** — server/services.py 里有两份 changelog_markdown()：前面那份写法正确（用 render_markdown + RELEASES），文件末尾那份调用的是根本不存在的 changelog_mod.markdown() 和 changelog_mod.get_changelog()。Python 取最后一份定义，于是前者永远不生效。
- **修复** — 删掉末尾那份错误实现。现在「关于」页能正常显示最近 4 个版本的完整更新日志。

## v4.0.3 · 高清修复：一键清空列表 · 修复跑完任务却被判失败
*2026-10-06*

这一版来自你的一条反馈：「高清修复板块没有清空选项，只有移除，要一个个点太麻烦」。顺手还挖出并修掉了一个更严重的问题 —— 在某些情况下所有文件都处理完了，任务却被标记为失败，产物全部不显示。

### 🗑 输入素材支持一键清空
- **清单顶部新增「清空」** — 文件列表上方多了一行统计与「🗑 清空」按钮，一次清掉全部已选文件。原来的逐个「移除」仍然保留，想单独去掉某一个还是可以用。
- **素材区新增「🗑 清空列表」按钮** — 和「导入最近下载」并排，列表较长时不用再往上滚。
- **任务进行中会拒绝清空并说明原因** — 避免你以为清掉了、其实任务还在按原来的清单跑。任务结束后立刻可以清空，不会卡住。

### 🐞 修复：处理完成后任务被判失败
- **问题现象** — 极少数情况下（例如点开始太快、参数还没填好），文件其实已经全部处理完，但界面报任务失败，一个结果都不显示。
- **根本原因** — 保存「上次使用的参数」时要把倍数字符串转成数字，读到空字符串会直接抛异常；而这个保存动作恰好发生在所有文件处理完之后，于是异常把整个任务拖成了失败。
- **修复方式** — 倍数字符串解析改为容错：空字符串、无法识别的写法一律当作「自动」。同时把「记住上次参数」整体隔离 —— 它只是顺手记个偏好，以后无论出什么问题都不会再影响你的处理结果。

### ✅ 验证
- **真实窗口 + 真实 GPU 跑通** — 64×64 测试图 → 超分产出成功，结果画廊正常显示，任务结束后清空列表生效。
- **冒烟测试扩充到 18 项** — 新增「倍数解析容错」「参数记忆不影响任务结果」「一键清空列表」三项回归检查，全部通过。

## v4.0.0 · 架构级改造 · 原生桌面窗口 · 彻底移除 Gradio · 修复黑窗
*2026-10-05*

这一版不再是「换皮」，而是把整个外壳换掉了：程序从「浏览器里打开的网页应用」变成真正的桌面程序，双击 exe 直接出现自己的窗口。同时修掉了长期困扰使用的 cmd 黑窗、启动静默崩溃与局域网零认证暴露三个问题。

### 🖥 变成真正的桌面程序
- **双击直接出程序窗口，不再打开浏览器** — 用 Windows 自带的 WebView2 承载原生窗口。原来双击后是拉起浏览器停在 127.0.0.1:7860，现在完全不需要浏览器。
- **彻底移除 Gradio** — 界面改为自研 FastAPI 后端 + 原生 HTML/CSS/JS 前端。启动更快、依赖更少、界面完全可控；业务逻辑与界面彻底分离，以后换界面不用再动处理逻辑。
- **界面重设计为两大板块** — 左侧导航「① 去水印 / ② 高清修复」，模型中心、素材库、工具箱、设置、关于收进同一侧栏，底部新增任务栏显示进行中的任务与总进度。

### 🩹 修复高清处理时 cmd 黑窗一直闪
- **根因** — 程序用 pythonw.exe（无控制台）启动，而所有 ffmpeg/ffprobe 调用都没有传 CREATE_NO_WINDOW。Windows 会为每个子进程新分配一个控制台窗口——一个视频闪 3~7 次，批量 20 个视频就是 80~140 个黑窗。
- **修复** — 统一在 run_quiet() 里补 CREATE_NO_WINDOW 与 stdin=DEVNULL，并补齐 probe_video、_pick_encoders 两处直接调用。处理后全程 0 黑窗。
- **顺带修掉** — 编码器探测用系统编码（GBK）解码 ffmpeg 的 UTF-8 输出、缺 ffmpeg 时误报「编码器不可用」、每个视频都重复探测一次编码器。

### 🩹 修复「双击没反应」（启动静默崩溃）
- **真实发生过的崩溃** — 日志里记录过 OSError: Cannot find empty port in range: 7860-7860 —— 端口被残留进程占用，而旧启动器在子进程死亡时静默退出，用户只看到「什么都没发生」。
- **修复** — 端口改为动态探测（7860~7879）并写运行时端口文件；启动失败会弹窗提示并指出日志位置，不再静默。
- **并且不会再残留进程** — 启动器新增 Windows 作业对象（Job Object）：即使启动器被强杀，Python 子进程也会被内核连带结束，不会再占着端口。

### 🔒 安全修复：局域网零认证暴露
- **问题** — 原来 lan_access=true 且密码为空时，程序会以 0.0.0.0:7860 无任何认证对外开放，素材 ZIP 下载路由也在其中。
- **修复** — 默认只监听本机；开启局域网访问但未设置密码时拒绝对外监听并记录警告。手机访问仍可用——需要开启并设置密码。

### 🧱 框架重设计（为长期维护铺路）
- **业务与界面彻底分离** — 原来 app.py 单文件 2600 行（界面 + 逻辑混在一起）；现在拆成 server/services.py（纯业务）、server/api.py（服务层）、frontend/（界面）三层，可各自独立测试。
- **任务系统重写** — 每个任务拥有独立的暂停/取消位与结构化事件流，修掉了「并发点击互相踩全局标志」的老问题；进度通过 SSE 实时推送。
- **去水印解析改为异步** — 原来在请求线程里串行解析，链接一多界面就卡死且无法取消；现在后台解析、有进度、可随时取消。

### 🔧 其他修复
- **视频转 GIF 文件名** — 原来会生成 xxx.gif_1，看图软件打不开；现在正确生成 .gif / _N.gif。
- **视频抽帧计数** — 不再把上一次运行残留的帧算进本次数量。
- **中文路径** — ffmpeg 调用补 encoding="utf-8"，中文路径不再乱码或抛异常。
- **子线程异常** — 现在会被记录到日志（threading.excepthook），不再静默丢失。
- **关闭程序** — 改为协作式关停：先通知任务停止、关闭服务释放端口，再退出，不会截断正在写入的文件。
- **去水印缓存** — 缓存有效期从 7 天改为 45 分钟（缓存里是数小时就过期的签名直链），并主动识别 401/403/410 死链，不再把重试次数浪费在过期地址上。
- **文件名加固** — 处理 Windows 保留设备名（CON/NUL/COM1…）、超长路径与 emoji 标题，避免下载时出现看不懂的 FileNotFoundError。
- **视频超分效率** — 修正目标尺寸计算（原来可能按 4 倍渲染再缩回 1080p，白烧显存与时间），并固定分块推理避免整帧 OOM 后静默变慢；任务结束后释放模型回收显存。

- **参数分「常用 + 高级」两层** — 输出长边上限、保存目录、补帧开关、人脸修复这些不常动的项，收进每张参数卡里的「高级参数」折叠面板，默认只露出模型和倍数两项。

- **混合批量同步卡片化** — 「混合批量」页也按「输入素材 / 图片参数 / 视频参数 / 操作 / 结果」分成了五张卡片，与另外两个子页风格统一。

### 🖼 程序图标
- **全新图标「棱镜」** — 红光射入、青光射出，寓意「模糊进、清晰出」，同时承载TikTok 红与抖音青双色品牌。提供 16 至 256 像素七种尺寸。
- **修复双托盘图标问题** — 旧版 C# 启动器与 Python 端各建了一个托盘图标，右下角会同时出现两个，且启动器用的是 Windows 默认空白图标。现已统一为同一个自绘图标。
- **网页标签页图标** — 浏览器标签页也会显示程序图标，不再是默认的空白页图标。

### 🔧 其他改进
- **版本号单一来源** — 版本号集中到 core/version.py，避免多处漏改导致显示不一致。
- **下载安全边界** — 「下载全部模型」只会下载已接入流水线的模型，不会误拉 DiffBIR / FlashVSR 这类 GB 级权重。

### 🐛 修复
- **4x-UltraSharp 无法加载** — 该权重用「旧版 ESRGAN 命名」（model.0 / model.1.sub.0.RDB1…），与 Real-ESRGAN 的命名（conv_first / body.0.rdb1…）不一致，加载会直接报错。现在会自动做键名映射，映射后先试装校验，通过才落盘。
- **realesr-animevideov3 无法加载** — 它是轻量版 SRVGGNet（16 层卷积），而代码里层数写死为 32 层，导致结构不匹配。现已改为按模型注册表读取各自的层数。
- **权重为裸 state_dict 时加载失败** — 官方权重带 params 外层，社区模型多为裸 state_dict，直接加载会报 KeyError: 'params'。现在会自动补齐外层包装。
- **模型下载源单一** — HuggingFace 在部分网络下不可达，现改为多镜像列表按序回退（优先国内镜像），并在界面显示当前使用的下载源。
- **冒烟测试新增模型推理检查** — 原来的测试只检查「文件是否存在」，不检查「能否真的跑起来」，导致上面这类权重格式问题漏到打包前才发现。现已加入「全部可选模型可加载推理」一项。
