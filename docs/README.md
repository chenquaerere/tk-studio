# TK去水印高清程序 v4.0.4

TikTok / 抖音 **去水印下载** + **图片/视频高清修复** 二合一本地工具。
**原生桌面程序**（自带窗口，不经过浏览器），数据不出电脑。

> **本仓库只包含源码。** 模型权重（约 1.35 GB）、内置 Python 运行时、ffmpeg、
> 虚拟环境均未入库，需要按下方「首次运行」自行准备。

---

## 📦 首次运行（从源码）

```bat
:: 1. 准备环境（Python 3.10 64 位）
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt

:: 2. 下载模型权重，放进 models\ （清单见下节）

:: 3. 启动
venv\Scripts\python.exe desktop.py
```

然后双击 `TK去水印高清程序.exe`（已编译的启动器），或在项目根执行上面的第 3 步。

## 🆕 v4.0.4 更新内容（本次）

### 🐞 修复「双击程序没有任何反应」（复发问题）

- **现象**：双击 `TK去水印高清程序.exe` 后无任何响应 —— 无窗口、无托盘、无报错。
- **根本原因**：启动器在启动 Python 前会向子进程环境写入两个 v3 遗留变量，使用的
  .NET `ProcessStartInfo.EnvironmentVariables` 是**大小写不敏感**字典；当系统环境里
  同时存在 `NO_PROXY` 与 `no_proxy` 时赋值直接抛 `ArgumentException`，而这段代码位于
  窗体 `Load` 中且**没有 try/catch**，异常发生在窗口显示之前 → 静默退出。
- **修复**：删除那两个无人读取的遗留变量（全项目已核实无引用），并给启动流程加兜底 ——
  `Main` / `Load` / `OnWatch` 任一层异常都会写入 `launcher.log` 并弹窗提示。
  以后启动失败一定留痕，不会再「什么都没发生」。

### 🐞 修复「关于」页面的更新日志显示失败

- **现象**：设置 → 关于 显示 `（更新日志读取失败：module 'core.changelog' has no attribute 'get_changelog'）`。
- **根本原因**：`server/services.py` 中 `changelog_markdown()` 被**定义两次**，后面那份调用
  了不存在的接口，把正确实现覆盖了。
- **修复**：删除重复定义。并用 AST 扫描全项目，又清除三处同类死代码（`models_cards_html`、
  `presets_html`、`update_notice_html`，其中旧的 `presets_html` 引用了不存在的变量 `badge`）。

### 🐞 修复「处理完成后任务却显示失败」

- **现象**：所有文件都处理完了、结果画廊也显示出产物，但任务被判为失败。
- **根本原因**：保存「上次使用的参数」的 `_remember_choices()` 位于**全部文件处理完成之后**，
  它内部解析放大倍数时遇到空字符串抛 `ValueError`，把整个任务拖成 failed，已跑完的产物
  全部不返回。
- **修复**：倍数解析改为容错（空值/「自动」/无法解析一律回退默认），且整个偏好保存过程
  加异常保护 —— **偏好保存永远不能影响任务结果**。

## 🆕 v4.0.0 更新内容（架构级改造）

### 🖥 从「网页应用」变成「真正的桌面程序」
- **双击 exe 直接出程序窗口** —— 原来会拉起浏览器并停在 `127.0.0.1:7860`；
  现在用系统自带的 WebView2 承载原生窗口，**完全不打开浏览器**
- **彻底移除 Gradio** —— 界面改为自研 FastAPI 后端 + 原生 HTML/CSS/JS 前端，
  启动更快、依赖更少、界面完全可控
- **界面重设计为两大板块**：左侧导航「① 去水印 / ② 高清修复」，设置与关于收进底部
- **新版前端自带**：顶栏状态胶囊（显卡 / 版本 / 服务状态）、阶段化进度条、
  任务栏汇总、结构化日志、SSE 实时进度推送

### 🩹 修复：高清处理时 cmd 黑窗一直闪（本次重点）
- **根因**：程序用 `pythonw.exe`（无控制台）启动，而所有 `ffmpeg`/`ffprobe` 调用
  都没有传 `CREATE_NO_WINDOW`。Windows 会为每个子进程新分配一个控制台窗口 ——
  一个视频会闪 **3~7 次**，批量 20 个视频就是 **80~140 个黑窗**
- **修复**：统一在 `core/utils.py` 的 `run_quiet()` 里补 `CREATE_NO_WINDOW`
  + `stdin=DEVNULL`，并补齐 `probe_video` / `_pick_encoders` 两处直接调用
- **实测**：处理全程 **0 黑窗**
- 顺带修掉：`_pick_encoders` 用系统编码（GBK）解码 ffmpeg 的 UTF-8 输出、
  缺 ffmpeg 时误报「编码器不可用」、每个文件都重复探测一次编码器

### 🩹 修复：程序会「双击没反应」（静默崩溃）
- `app.log` 里真实记录过 `OSError: Cannot find empty port in range: 7860-7860`，
  而旧启动器在子进程死亡时**静默退出**，用户只看到「什么都没发生」
- **修复**：端口改为动态探测（7860~7879）+ 写运行时端口文件；
  启动失败**弹窗提示**并指出日志路径
- **同时**：启动器新增 Windows **作业对象（Job Object）** ——
  即使启动器被强杀，Python 子进程也会被内核连带结束，
  不会再残留进程占着端口（这正是上次崩溃的直接原因）

### 🔒 安全修复：局域网零认证暴露
- 原来 `lan_access: true` + 空密码 = `0.0.0.0:7860` **无任何认证**对外开放
  （含素材 ZIP 下载路由）
- **修复**：默认仅监听本机；开启局域网访问但未设密码时**拒绝**对外监听并记录警告

### 🧱 框架重设计（为后续维护铺路）
- 业务逻辑从 `app.py` 单文件（2600 行）抽到 **`server/services.py`**，
  **与界面完全无关**（可用「屏蔽 gradio」的测试证明）
- 新增 **`server/jobs.py`**：每个任务拥有**独立的暂停/取消位**与结构化事件流，
  修掉「并发点击互相踩全局标志」的老问题
- 新增 **`server/api.py`**：34 条 REST 路由 + SSE 实时进度
- 新增 **`server/state.py` / `ui/bus.py`**：事件与状态的数据契约

### 🔧 其他修复
- 视频转 GIF 输出名修正（原来会生成 `xxx.gif_1`，看图软件打不开）
- 视频抽帧计数改为增量（不再把上次残留的帧算进去）
- 中文路径下 ffmpeg 调用补 `encoding="utf-8"`（原来中文路径会乱码/抛异常）
- 子线程异常现在会被记录（`threading.excepthook`），不再静默丢失
- 关闭程序改为**协作式关停**：先通知任务停止、关闭服务释放端口，再退出
- 版本号统一到 `core/version.py` 单一来源

## 运行环境
- Python 3.10+，GPU（CUDA）优先，无 GPU 也可用 CPU
- 依赖见 `requirements.txt`（不再需要 gradio —— v4.0 已完全移除）
- **RTX 50 系（Blackwell）需 PyTorch ≥ 2.7 + CUDA 12.8**，本机验证环境为 `torch 2.11.0+cu128`
- 模型权重位于 `models\`，人脸修复权重位于 `gfpgan\weights\`
- 桌面窗口依赖 **WebView2 运行时**（Win10/11 通常已内置）

## 快速启动
**方式一（推荐）：双击 `TK去水印高清程序.exe`**
启动器会自行寻找可用的 Python 环境、拉起本地服务、打开原生窗口，并自动修复
`venv\pyvenv.cfg` 的 home 路径（换目录、换机器也能自愈）。

**方式二：双击 `启动-高清去水印.bat`**

**方式三：手动运行**
```
venv\Scripts\python.exe desktop.py
```

> v4.0 起**入口是 `desktop.py`**，不再是 `app.py`（已废弃归档），也不会再打开浏览器。
> 服务默认监听 `127.0.0.1` 上的空闲端口，端口占用会自动换一个（7860~7879）。

### 关于 exe
`TK去水印高清程序.exe` 是轻量启动器（约 35 KB），用 C# 编写、Job Object 绑定子进程 ——
强制结束启动器不会留下孤儿 Python 进程。启动失败会写 `launcher.log`。

### 完整版（自包含）
完整版压缩包内置 Python 运行时（`python-runtime`）与全部依赖（`venv`）及模型权重，
**解压到任意电脑任意位置即可双击运行**，无需单独安装 Python 或依赖。
用 `scripts\package.py` 可自行出包。

### 重新编译启动器 exe
修改 `_launcher.cs` 后需手动重编译（Windows 自带 csc，无需安装 Visual Studio）：

```
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:winexe ^
  /platform:x64 /win32icon:assets\icon.ico /out:TK去水印高清程序.exe ^
  /r:System.Windows.Forms.dll /r:System.Drawing.dll _launcher.cs
```

## 抖音解析技术说明

- `tiktok/sm3.py`：纯 Python 国密 SM3 哈希

- `tiktok/douyin.py`：抖音解析引擎（ttwid 注册 + detail API + 多级兜底）
