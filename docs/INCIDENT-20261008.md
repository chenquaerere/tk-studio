## 事件经过

`scripts/verify_w3.py` 的「采集任务启动校验」一节本意是**只验证参数校验**，
其中一条用例传入空账号列表：

```python
req(port, "/api/collector/collect", "POST", {"account_ids": []})
```

预期返回 400。但当时的实现是：

```python
ids = [str(x) for x in (payload.get("account_ids") or [])]
if ids:
    accounts = [_get_account(i) for i in ids]
else:
    region = payload.get("region")           # 也是空的
    want = None if region in (None, "", ...) else region
    rows = c.db.list_accounts(enabled_only=True, region=want)   # ← 静默变成"全部 21 个账号"
    accounts = [...]
```

于是空列表被**隐式兜底为"全部启用账号"**，创建了 `TASK-20261008-001`，
后台线程随即调用 `CollectEngine.run()`。

`run()` 的第一步（这是采集器的既定设计，用于「替换式记录」）就是：

```python
for acc in accounts:
    self.db.delete_videos_for_account(acc.account_id)   # ← 84 条作品在这里被删
```

删除发生在打开浏览器之前，所以即使脚本随即退出、线程被中断，
数据也已经没了。**这是"参数默认值"演变成"数据破坏"的典型路径**：
一个看似无害的兜底逻辑，作用在不可逆的写操作上。

## 修复措施（已落地）

在 `server/collector_api.py::start_collect` 增加**显式范围闸门**：

```python
if not ids and not want_region and not payload.get("all"):
    raise HTTPException(400, "未指定采集范围：请传 account_ids、region，"
                             "或显式传 all=true 表示全部启用账号")
```

即："全选"必须由调用方**显式声明** `all=true`，绝不隐式兜底。
空请求、空列表一律 400。验收脚本已补两条对应用例。

## 沉淀为通用规则

1. **不可逆写操作之前，绝不使用"参数缺省 → 更大范围"的兜底**。
   默认值应当是"什么都不做"，而不是"做最多"。
2. **批量删除型操作要求显式确认范围**（本项目的采集是"替换式记录"，
   启动即删除所选账号既有记录）。
3. **验收脚本禁止调用会写业务数据的端点**；本次教训是"为了验证参数校验
   而调用了真实接口"，正确做法是把校验逻辑抽成纯函数单测。
4. **原始数据始终只读**：本次能零损失恢复，唯一原因是自 W0 起
   原部署目录的数据库从未被写入（所有读取都走 `mode=ro` URI）。
   这条纪律的价值在事故里被验证。

## 二、W4 浏览器交互验证误改账号启用状态

- **发生时间**：2026-10-08 16:05 前后（GMT+8）
- **发现时机**：`scripts/shots_w4.py` 断言「开始采集按钮不应处于禁用态」失败，
  回查 DOM 见账号列表行被标记 `disabled`
- **影响范围**：账号 `anthonyhansen1935` 的 `enabled` 被切换一次
- **最终损失**：**无**

### 事件经过

W4 的「8 条 UX 契约」中有一条是**「整行可点」**。在**账号管理页**，
整行点击绑定的是 `PATCH /api/collector/accounts/{id}`（切换启用 / 停用），
因此该断言实际执行了一次**会落库的写操作**。

发现后逐字段比对：仅 `enabled` 被翻转、`updated_at` 被刷新。
连点两次把 `enabled` 翻回原值，再把 `updated_at` 还原为
`2026-10-07 21:25:39`，全表逐行比对与原库一致。

### 加固措施（已落地）

1. 验收脚本把「整行可点」的验证**移到「采集任务」页** ——
   那里的整行点击只改内存勾选集合（`S_.picked`），不触网、不落库。
2. `shots_w4.py` 文档串写明纪律：
   **「绝不点击会落库的控件（启用停用开关 / 保存 / 清空 / 删除 / 开始采集）」**。
3. 该纪律与 W3 的「验收脚本禁止调用会写业务数据的端点」合并为同一条通用规则：
   **验收只允许 (a) 只读请求；(b) 内存态交互。**

对照：`settings.last_backup_date` 由 `CollectorServices(auto_backup=True)`
在服务启动时写入的每日备份记帐，**属正常记帐**，不算数据扰动。
